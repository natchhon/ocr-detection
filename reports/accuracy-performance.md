# OCR accuracy and performance implementation report

Date: 2026-11-24. This report records the initial implementation before an original
card was supplied. Current single-card calibration and remaining errors are in
[the follow-up report](ais-calibration.md). These are not production acceptance results.

## Audit and baseline

The repository initially had a working PyTorch Chakkhu provider, one OpenCV contour
detector, upload checks, and a thin service. Parsers, preprocessing modules, tests,
benchmark scripts, README, typed pipeline configuration, and structured fields were
missing. The user had changed Makefile `HOST` from `0.0.0.0` to `localhost`; that change
was preserved. Existing model files, `.env`, and infrastructure configuration were
not modified. Generated bytecode is now ignored, not deleted.

Environment: Python 3.10.12 in the existing `.venv`; Intel i7-1355U, 12 logical CPUs;
Torch 2.14.1+cpu with 10 default intra-op threads; CUDA unavailable; Pillow 12.3.0;
OpenCV 5.1.0.95; NumPy 2.2.6. Small test/lint dependencies and optional ONNX Runtime
1.23.2 were installed. The separate pinned ONNX INT8 model was downloaded explicitly
for compatibility testing; the working PyTorch model was retained.

The installed PyTorch snapshot metadata identifies revision
`e3c8ff8ead6a3fa28d39a4f4fa779e92bbc4ad7d`. Its actual reader signature supports PIL
images and `beam`, `lam`, `batch`, `confidence`, and optional `checker`. Its internal
preprocessing converts to grayscale, rescales to height 64, and caps width at 2400.
The adapter uses only inspected parameters, keeps beam 4/batch 16/lam 0.5 defaults,
and leaves the general spelling checker disabled. The original adapter wrote PNG
crops to temporary files and removed low-confidence predictions.

No original student-card image or verified ground truth was supplied or found.
Only upstream model documentation images were present. They were not treated as
student-card examples. Therefore an original-card accuracy baseline, AIS ROI
calibration, vertical Khmer orientation on the actual card, and real Khmer-name
accuracy remain unmeasured. The previously cited 19,456/57,027 ms screenshot results
are not used as comparison baselines.

Before implementation, a deterministic 800×500 synthetic English image was run
through the existing provider. SHA-256 of its PNG bytes:
`cb7c8a6cb9009e24927375fe27d5e95ece3274c08200756a6f176388bddcde0e`.
The expected three lines were `SYNTHETIC SCHOOL`, `TEST00001`, and `2026 - 2027`.
Model loading took 788.31 ms. The three recognition calls took **886.06, 649.10,
666.32 ms**, without a separate warmup. The detector split the year into two blocks;
mean OCR confidence was 0.996 despite that layout error. See
[baseline measurements](baseline-existing-pipeline.json).

## Measured comparisons

The following runs used the identical generated English text/image, one warmup
pass, and five timed repeats. Model load and image upload/decode are excluded from
pipeline times. These are single-image smoke measurements on an uncontrolled local
machine, not independent-document latency distributions. P95/P99 are not reported.
The initial three-call baseline used different warmup conditions and is not a
statistically valid before/after speedup estimate.

| Provider / preprocessing | Threads | Decoder | Mean ms | P50 ms | CER | Whitespace WER |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| PyTorch / RGB | runtime default (10) | beam 4 | 703.98 | 701.24 | 2.63% | 0% |
| PyTorch / grayscale | runtime default (10) | beam 4 | 691.23 | 693.04 | 2.63% | 0% |
| PyTorch / CLAHE | runtime default (10) | beam 4 | 751.90 | 771.19 | 2.63% | 0% |
| PyTorch / Khmer denoise | runtime default (10) | beam 4 | 779.25 | 767.48 | 2.63% | 0% |
| PyTorch / RGB | 4 | beam 4 | 1167.76 | 1165.64 | 2.63% | 0% |
| PyTorch / RGB | 4 | CTC only | 450.28 | 439.60 | 2.63% | 0% |
| ONNX INT8 / RGB | runtime default | beam 4 | 1337.41 | 1340.08 | 2.63% | 0% |
| ONNX INT8 / RGB | 4 | beam 4 | 740.36 | 753.72 | 2.63% | 0% |

The one CER edit in the contour runs is a line separator where the expected year
contains a space; whitespace WER does not penalize that distinction. This is a
segmentation issue, not evidence of correct layout or Khmer recognition. No field
scores are computed when the fixture has no named field labels.

Original RGB remains the default because these data show no accuracy improvement
from enhancements. CTC-only was faster on this synthetic sample but is opt-in;
Khmer accuracy has not been established. A blanket four-thread setting was not
adopted because its measured effect differed between providers. In-memory batching
removes crop-file I/O, but no production speedup is claimed from that alone.

## ROI mechanics and an observed recognition failure

A separate **synthetic tuning** card was generated with a grey photo placeholder
and three known text fields. It was placed on a dark background to exercise card
boundary detection. The detector rectified 1000×700 input to 799×499; visual
inspection confirmed that all three ROIs enclosed the text and excluded the photo.
The template is specific to this synthetic layout and is never used as AIS data.

With RGB, default PyTorch threads/beam, one warmup and five repeats, the ROI run
averaged **492.91 ms**, P50 **495.31 ms**. It returned three blocks. CER was **2.63%**,
whitespace WER **16.67%**, and field exact match **2/3 (66.67%)**. School name and
academic year matched; **student-ID exact match was 0/1**. The model confused one
identifier character. No dictionary repaired or hid the error. Khmer-name accuracy
is unmeasured because no Khmer-name label was present.

This is not the same input as the contour benchmark and is not a valid speedup
comparison. It demonstrates why ROI throughput and high confidence cannot replace
field-level accuracy checks. See [ROI measurements](synthetic-roi.json). Repeat with:

```bash
.venv/bin/python -m scripts.create_synthetic_dataset /tmp/new-ocr-fixture
.venv/bin/python -m scripts.benchmark --manifest /tmp/new-ocr-fixture/manifest.json --template /tmp/new-ocr-fixture/template.json --variants original --runs 5 --output /tmp/new-roi-report.json
```

## ONNX compatibility and limits

The adapter uses the inspected upstream `Chakkhu(repo, int8=True, threads=...)`
constructor and `.read(images, beam, lam, batch, confidence)` interface from revision
`8d7373487dfb56e4f13ba26cea31e1f858bd6ddd`. Downloaded inference source SHA-256 matched
the source inspected before execution:
`c5054cb6ab9cb70a647229d95b085da7c4ff724191b295a86aa3f0bff99029ee`.
The local normalization source was also inspected. Models are local-only at startup;
missing files fail rather than silently downloading. Source inspection is not a
comprehensive third-party security audit.

Real ONNX inference passed the synthetic benchmark. Default-thread ONNX model
loading was 180.89 ms; cumulative process peak RSS was 422.89 MiB, versus 667.02 MiB
for the PyTorch RGB comparison process. The ONNX default-thread run was slower on
this sample. Peak RSS is not an isolated model-memory measurement, and preprocessing
variants in one process share a cumulative high-water mark.

The two snapshots are not proven identical training/export weights. ONNX also caps
line width at 4096 rather than 2400. Differences therefore cannot be attributed
solely to INT8 quantization. Published code/model cards state Apache-2.0; attribution
and deployment license review remain necessary. PyTorch remains the default.

## Verification and outstanding evidence

`make check` passes syntax compilation, application imports, Ruff lint, and formatting.
The automated suite covers configuration rejection, NFC, category suggestions,
unchanged personal names/IDs, required/missing/duplicate fields, both rotation
signs, normalized ROI bounds, perspective mapping, geometric fallback, prediction
counts, empty/uncertain results, invalid scores, thread serialization, provider
switching, parameter forwarding, upload errors, EXIF coordinates, private logging,
checksums, metric calculations, dataset split/checksum validation, and lifecycle.
The final suite passed **55 tests in 1.11 seconds**. API tests required execution
outside the sandbox because Starlette's threaded test client stalled inside it;
they passed there.

Remaining acceptance work requires authorized originals and verified transcriptions:

- Calibrate AIS geometry and education-line rotation against rectified originals;
  this was pending at the time of this initial report; see the follow-up for
  the subsequently supplied sample and calibrated template.
- Establish a disjoint held-out evaluation set and real CER, Khmer-tokenized WER if
  desired, student-ID, and Khmer-name exact-match accuracy. Current WER is explicitly
  whitespace-based, not Khmer linguistic word segmentation.
- Validate institution-specific ID/year/campus formats before configuring validators.
- Compare PyTorch/ONNX and preprocessing on the same held-out set before selecting
  production settings. Check real portrait, landscape, glare, blur, skew, and
  screenshot inputs. Card geometry is not document identity or authenticity.
- Add authentication, TLS, concurrency limits, and retention controls before external
  deployment. No deployment or training was performed; the optional web debug UI
  remains deferred while core real-card accuracy is unverified.
